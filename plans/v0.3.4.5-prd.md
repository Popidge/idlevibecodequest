# PRD: v0.3.4.5 - Game Logic Refactor (Single Source of Truth)

**Objective:** Centralize all game economy math into a unified "System Modifiers" pipeline using Svelte 5 runes. Eliminate distributed magic numbers and multiplicative spiraling by enforcing an additive multiplier architecture.

**Context:** Currently, bonuses are scattered across constants, save state (`prestige.bonuses`), and getter functions. This refactor creates a derived state engine that calculates total bonuses on-the-fly from unlocked nodes/upgrades.

---

## Architecture Overview

1.  **`SystemModifiers` Interface:** A comprehensive map of every possible numeric variable in the game (multipliers, flat bonuses, boolean flags).
2.  **`activeModifiers` Derived Rune:** A single `$derived.by` computation in the Store that aggregates unlocked Tech Tree nodes and Prestige Path buffs into one `SystemModifiers` object.
3.  **Additive Math Standard:** `Final = (Base + Flat) * (1 + Sum(Multipliers))`
4.  **Priority Debt Logic:** Special handling for Tech Debt mechanics (Zen/Whisperer) via boolean flags.

---

## Phase 1: Type Definitions & Constant Standardization

**Goal:** establish the data structures before touching the logic.

### Tasks
1.  **Define `SystemModifiers` in `types.ts`:**
    *   Create an interface containing all economy levers:
        *   **Multipliers (Additive):** `moneyMultiplier`, `locMultiplier`, `credMultiplier`, `prestigePointMultiplier`.
        *   **Flat Bonuses:** `locPerClickFlat`, `passiveLocRateFlat`, `startingCashFlat`, `credThresholdReduction`.
        *   **Debt Mechanics:** `debtAccumulationReduction`, `debtPenaltyReduction`, `debtClearingEfficiency`.
        *   **Special Flags:** `unlockLegacyWhisperer`, `unlockCodeZen`, `unlockVerticalIntegration`.
2.  **Refactor `TechTreeNode` in `types.ts`:**
    *   Remove `effect` (string) and `effectValue` (number).
    *   Add `modifiers: Partial<SystemModifiers>`.
3.  **Update `constants.ts`:**
    *   Rewrite `TECH_TREES` and `PRESTIGE` constants to use the new `modifiers` object format instead of string/value pairs.

### Critical Pattern (Types)
```typescript
export interface SystemModifiers {
    moneyMultiplier: number; // 0.5 = +50%
    locPerClickFlat: number; 
    unlockCodeZen: boolean;  // Boolean flag for special logic
    // ... all other modifiers
}
```

### Acceptance Criteria
*   [ ] `types.ts` compiles with no references to the old `TechTreeEffect` type.
*   [ ] All nodes in `constants.ts` strictly adhere to `Partial<SystemModifiers>`.

## Phase 2: The Store Engine (Core Refactor)

**Goal:** Implement the central calculation engine in `store.svelte.ts`.

### Tasks
1.  **Implement `activeModifiers` Derived Rune:**
    *   Create a `$derived.by` block in `GameStore`.
    *   Initialize a default `0/false` modifiers object.
    *   Iterate through `this.gameState.prestige.techTrees` *once*.
    *   Additively merge numeric modifiers; toggle boolean flags to `true` if present.
2.  **Refactor Resource Getters:**
    *   Update `effectiveClickPower`, `effectivePassiveLocRate`, and `effectivePassiveIncome`.
    *   Logic must follow: `(Base + Modifiers.flat) * (1 + Modifiers.multiplier)`.
3.  **Implement New Debt Logic:**
    *   Refactor `effectiveTechDebtPenalty`.
    *   **Priority 1:** If `activeModifiers.unlockCodeZen` is true → return `1 / max(0.01, penalty)`.
    *   **Priority 2:** If `activeModifiers.unlockLegacyWhisperer` is true → return `1.0`.
    *   **Default:** Return `penalty + ((1 - penalty) * activeModifiers.debtPenaltyReduction)`.

### Critical Pattern (Store)
```typescript
activeModifiers = $derived.by(() => {
    const mods = { /* ...defaults... */ };
    // Loop through purchased nodes, sum numbers, OR booleans
    // Return final mods object
    return mods;
});
```

### Acceptance Criteria
*   [ ] `activeModifiers` automatically updates when a test node is "purchased" (added to state).
*   [ ] `effectiveClickPower` correctly calculates `Base + Flat` before applying `Multiplier`.
*   [ ] Code Zen correctly inverts the penalty when the flag is active.

## Phase 3: Cleanup & Integration

**Goal:** Remove legacy code and connect the new engine to game actions.

### Tasks
1.  **Remove Legacy Save Data:**
    *   Remove `prestige.bonuses` from `GameState` interface and default state.
    *   Remove logic that manually adds bonuses to `prestige.bonuses` during prestige/purchases.
2.  **Update Game Actions:**
    *   Update `shipProject` to use `store.activeModifiers.moneyMultiplier` (via getters/helpers) instead of local calculations.
    *   Update `accumulateDebt` functions to use `store.activeModifiers.debtAccumulationReduction`.
3.  **Update Components (UI):**
    *   Ensure the Tech Tree UI correctly reads `node.modifiers` for display text.
    *   Ensure Stat panels read from `store.activeModifiers` for "Current Bonus" tooltips.

### Acceptance Criteria
*   [ ] The application compiles with no errors.
*   [ ] `prestige.bonuses` no longer exists in `localStorage` on a new save.
*   [ ] Tech Tree tooltips correctly describe effects based on the new `modifiers` object.

# **VIBE CODE GURU v0.4 PRODUCT REQUIREMENTS**
### *A PRD for migrating from functional prototype to engaging idle clicker*

## **PHASE 1: Core Tech Debt System**
**Objective:** Introduce the maintenance mechanic that creates strategic tension and prevents infinite exponential growth.

### **Step 1.1: Tech Debt Accumulation**
**Description:** Every player action (prompt click) increases a "tech debt" value that acts as a multiplier penalty on all earnings.

**Mechanics:**
- Each prompt click adds 0.008 base debt + 0.0001 per project shipped (cumulative)
- Debt caps at 50% maximum
- Debt applies a squared penalty: `effectiveIncome = rawIncome × (1 - debt)²`
- Debt is displayed as a percentage in the stats panel

**Acceptance Criteria:**
- [ ] Debt value persists in save state
- [ ] Debt increases on every prompt click
- [ ] Debt never exceeds 0.5 (50%)
- [ ] Debt visibly impacts LoC/sec and $/sec earnings in real-time
- [ ] Debt display turns amber and flashes when >40%

**Design Notes:** The penalty should feel meaningful but not crushing at 30-40% debt. At 50% debt, earnings should be ~25% of normal, creating urgency to clear it.

### **Step 1.2: Debt Reduction Mechanics**
**Description:** Players can spend resources to actively reduce tech debt, creating a resource allocation decision.

**Mechanics:**
- Two payment options: LoC or Cash
- Cost: 800 LoC per 0.01 debt cleared, OR 4000 Cash per 0.01 debt cleared
- Minimum reduction: 0.01 debt
- Maximum reduction: current debt amount
- Payment buttons only appear when debt >0.4

**Acceptance Criteria:**
- [ ] Debt reduction buttons appear in stats panel when debt >40%
- [ ] Clicking opens a modal to select amount (0.01 to current debt)
- [ ] Modal shows both payment options with costs
- [ ] Successful payment reduces debt and resources correctly
- [ ] Modal closes automatically after payment

**Design Notes:** The cost should feel significant but fair. Clearing 0.10 debt (10%) should cost roughly 30-60 seconds of income at mid-game levels.

### **Step 1.3: Maintenance Mode (Offline Progression)**
**Description:** When the browser is closed, the game enters "maintenance mode" where progress continues at a reduced rate and debt is frozen.

**Mechanics:**
- On game load, calculate time since last save
- Generate offline LoC at 10% of normal auto-click rate
- Generate offline Cash at 10% of normal passive income
- **Crucially:** Tech debt does NOT increase while offline
- Display a welcome-back message showing offline gains

**Acceptance Criteria:**
- [ ] Game tracks last save timestamp
- [ ] On load, calculates hours offline and applies 10% progress
- [ ] Offline gains are displayed in a non-intrusive message
- [ ] Tech debt remains unchanged from when player closed the game
- [ ] Message disappears after 5 seconds or on any click

**Design Notes:** This is anti-FOMO design. Players should feel comfortable closing the game. The 10% rate is generous enough to feel rewarding but not so high that active play is devalued.

## **PHASE 2: UI/UX Engagement Layer**
**Objective:** Add visual feedback and strategic guidance that keeps players informed and engaged without being overwhelming.

### **Step 2.1: Progress Bars**
**Description:** Visual progress indicators for key goals (next upgrade, prestige threshold).

**Mechanics:**
- Progress bar appears in stats panel showing LoC progress toward next cheapest upgrade
- Bar fills left-to-right with a subtle gradient
- Text overlay shows current/max values (e.g., "1.2K / 2.5K LoC")
- Updates in real-time as player gains LoC

**Acceptance Criteria:**
- [ ] Progress bar appears below core stats
- [ ] Automatically tracks cheapest available upgrade
- [ ] Fills smoothly as LoC increases
- [ ] Reaches 100% when upgrade is affordable
- [ ] Updates target immediately after purchase

**Design Notes:** The progress bar should be 120-150px wide, 16px tall, with a subtle green gradient. Text should be 10px monospace, centered vertically.

### **Step 2.2: Tech Debt Warning System** - ALREADY IMPLEMENTED+ITERATED
**Description:** Visual and interactive elements that alert players when debt becomes problematic.

**Mechanics:**
- Debt percentage displayed in stats panel
- At >10% debt, text turns amber and blinks slowly
- "CLEAR" button appears next to debt display when >10%
- Button opens debt reduction modal

**Acceptance Criteria:**
- [ ] Debt display is normally green (text-primary)
- [ ] Debt display turns amber and blinks when >10%
- [ ] "CLEAR" button appears only when >10%
- [ ] Button is clickable and opens modal
- [ ] Button is hidden when debt ≤10%

**Design Notes:** The blink should be subtle (1s cycle, 50% opacity) - not seizure-inducing. The button should feel like an emergency option, not a constant UI element.

### **Step 2.3: Strategic Hint System**
**Description:** Contextual tips that appear based on game state to guide optimal play.

**Mechanics:**
- Hints appear in bottom-right corner as small pop-ups
- Maximum 2 hints shown at once
- Hints appear based on conditions:
  - Debt >40%: "Tech debt high - consider clearing!"
  - Debt <10%: "Debt low - good time to save LoC"
  - Unlocks >60%: "Prestige available soon!"
- Hints fade out after 10 seconds or on click

**Acceptance Criteria:**
- [ ] Hints appear based on game state conditions
- [ ] Maximum 2 hints visible simultaneously
- [ ] Hints are dismissible (click to hide)
- [ ] Auto-dismiss after 10 seconds
- [ ] Do not reappear for 60 seconds after dismissal

**Design Notes:** Hints should feel helpful, not nagging. Use a subtle slide-in animation. Position bottom-right to avoid obscuring main UI.

## **PHASE 3: Prestige Loop**
**Objective:** Implement the core meta-progression system that gives players permanent bonuses and a reason to reset.

### **Step 3.1: Prestige Threshold & Points**
**Description:** Players can "prestige" when they've unlocked 70% of upgrades, earning points based on total cash earned.

**Mechanics:**
- Prestige becomes available when 70% of all upgrades (vibeCode + delegation) are owned
- Prestige points = floor(log10(total cash earned this run + 1))
- Minimum 1 point, typical first run: 3-5 points
- Prestige button appears (prominently but not obnoxiously) when available

**Acceptance Criteria:**
- [ ] System tracks percentage of upgrades owned
- [ ] Prestige button appears at exactly 70% threshold
- [ ] Button is visually distinct (amber border, subtle glow)
- [ ] Points calculation matches log10(cash) formula
- [ ] Minimum 1 point even with low cash

**Design Notes:** The button should feel like an achievement unlock, not a nag. Place it in the title panel or as a centered overlay. Make it clear this is optional but beneficial.

### **Step 3.2: Prestige Path Selection**
**Description:** Three distinct prestige paths offering different bonuses for the next run.

**Mechanics:**
- **Big Company Buyout**: Starting cash boost + cash income multiplier
  - Starting cash: +5,000 per prestige point
  - Cash multiplier: +20% per prestige point (additive)
- **Tech Bro Nirvana**: LoC generation multiplier
  - LoC multiplier: +15% per prestige point (additive)
- **The Linus Effect**: Credibility gain multiplier
  - Cred multiplier: +25% per prestige point (additive)

**Acceptance Criteria:**
- [ ] Modal appears when prestige button clicked
- [ ] Modal clearly explains all three paths with numbers
- [ ] Player must select one path to proceed
- [ ] Bonuses are applied immediately after prestige
- [ ] Bonuses persist across all future runs

**Design Notes:** Path choice should be permanent for that prestige (no take-backs). Show current bonus totals to help players plan long-term strategy. Thematic icons help differentiate paths.

### **Step 3.3: Prestige Reset Logic**
**Description:** Resetting the game state while preserving prestige bonuses and applying new ones.

**Mechanics:**
- On prestige, reset:
  - All resources (LoC, Cash, Cred) to 0
  - All upgrades to level 0
  - All projects to count 0
  - Tech debt to 0
  - Projects shipped counter to 0
- Preserve:
  - Prestige count and path history
  - All earned prestige bonuses
  - Tech tree unlocks
- Apply starting bonuses based on path chosen

**Acceptance Criteria:**
- [ ] All game state resets except prestige data
- [ ] Starting bonuses applied immediately (e.g., starting cash)
- [ ] UI updates to reflect new multipliers
- [ ] Save file marks this as a new "run" but keeps prestige data
- [ ] Player can prestige again in the new run

**Design Notes:** The reset should feel like a "new game+" not a punishment. Show a summary screen: "Previous run: 7m 32s, Cash: $45,230, Prestige points: 4" before the reset.

## **PHASE 4: Tech Tree Progression**
**Objective:** Long-term progression system that gives players permanent upgrades across prestige runs.

### **Step 4.1: Tech Tree Structure**
**Description:** Three trees (one per prestige path) with 10 nodes each, unlocked with prestige points.

**Mechanics:**
- Each tree has 10 nodes in linear sequence (must buy previous to unlock next)
- Nodes cost 1, 3, 5, 10, 15, 20, 25, 30, 35, 40 prestige points respectively
- Nodes provide permanent bonuses:
  - Buyout: Starting cash, auto-purchase unlocks, cash multipliers
  - Nirvana: LoC multipliers, click power boosts, offline progress bonuses
  - Linus: Cred multipliers, unlock speed, project cost reductions

**Acceptance Criteria:**
- [ ] Three separate tech trees accessible via tabs
- [ ] Nodes displayed in vertical list with connecting lines
- [ ] Purchased nodes visually distinct (green border, checkmark)
- [ ] Available but unpurchased nodes show cost and are clickable
- [ ] Locked nodes (prerequisite not met) are grayed out
- [ ] Prestige point total displayed at top of each tree

**Design Notes:** The tree should feel substantial - each node should be a meaningful upgrade, not +1% fluff. The 1-3-5-10-15-20-25-30-35-40 cost progression gives a natural sense of increasing investment.

### **Step 4.2: Tech Tree Effects**
**Description:** Each node provides a unique permanent bonus that modifies core gameplay.

**Example Nodes (to be implemented):**
- **Buyout Path:**
  - Seed Funding: +5,000 starting cash
  - Angel Investor: +15,000 starting cash
  - Series A: +30% cash multiplier
  - Acqui-hire: Unlock auto-purchase of upgrades <10% of current LoC
  - IPO: +50% prestige point gain
- **Nirvana Path:**
  - Copilot+: +10% LoC per click
  - Vibe Streak: +20% LoC per click
  - Prompt Engineer: +30% LoC per click
  - AI Whisperer: +50% LoC per click
  - AGI Integration: +100% LoC per click
- **Linus Path:**
  - OSS Contributor: +20% cred gain
  - Kernel Commit: +30% cred gain
  - Maintainer: +50% cred gain
  - Linus Blessing: +100% cred gain
  - GitHub Star: Unlock all projects 10 cred earlier

**Acceptance Criteria:**
- [ ] Each node has a unique, meaningful effect
- [ ] Effects stack additively with prestige bonuses
- [ ] Effects persist across all future runs
- [ ] Some nodes unlock new mechanics (auto-purchase, offline boosts)
- [ ] Node descriptions clearly explain the effect

**Design Notes:** Mix of passive bonuses and unlocks. The final node in each tree should feel game-changing. Auto-purchase is a good example - it removes tedium for late-game players.

## **PHASE 5: Balance & Polish**
**Objective:** Tune numbers and add final polish to create a satisfying 6-8 minute first-run experience.

### **Step 5.1: Core Balance Tuning**
**Description:** Set final numbers for costs, incomes, and scaling to hit target playtimes.

**Target Metrics:**
- First run to prestige: 6-8 minutes
- Second run: 4-5 minutes (30-40% faster)
- Third run: 3-4 minutes
- Tech debt peaks at 40-50% just before prestige
- First prestige yields 3-5 prestige points

**Balance Values:**
- Upgrade cost multiplier: 1.5x per level
- Tech debt per prompt: 0.008 base + 0.0001 per project shipped
- Debt reduction cost: 800 LoC or 4,000 Cash per 0.01 debt
- Prestige point formula: floor(log10(total cash + 1))
- Prestige bonuses: +5,000 cash / +15% LoC / +25% cred per point

**Acceptance Criteria:**
- [ ] First run playtested to 6-8 minute target
- [ ] Second run feels noticeably faster
- [ ] Tech debt creates meaningful decision point at ~4 minutes
- [ ] Prestige point gain feels rewarding (3-5 points typical)
- [ ] No upgrade feels like a "wall" (time-to-purchase >2 minutes)

**Design Notes:** These numbers are starting points. The AI agent should playtest and adjust if first run is <5 min or >10 min. The goal is a smooth curve, not a perfect formula.

### **Step 5.2: Visual & Audio Polish**
**Description:** Add subtle animations and feedback to make interactions satisfying.

**Polish Elements:**
- Click button: subtle scale animation on press (0.98x)
- Upgrade purchase: green flash on the purchased item
- Debt cleared: brief green glow on stats panel
- Prestige: screen transition animation (fade to white, back to game)
- Floating text: +LoC numbers float up and fade (already exists, ensure it still works)

**Acceptance Criteria:**
- [ ] All button clicks have immediate visual feedback
- [ ] Purchases are celebrated (flash, glow, or similar)
- [ ] No animation exceeds 300ms duration
- [ ] Animations are subtle, not distracting
- [ ] Performance impact is negligible

**Design Notes:** Polish should enhance feedback, not create spectacle. The terminal theme calls for subtle, retro-style animations. Think 8-bit, not AAA game.

- Color contrast meets WCAG AA standards (green on black does)
- Keyboard navigation support (Tab between buttons, Enter to activate)

- Chrome, Firefox, Safari (latest 2 versions)

# v0.4 Tuning Page Plan

## Overview

Create a development-only tuning page that allows game designers to model gameplay timing metrics by importing functions and constants from the game code. This page will help balance the game by simulating different scenarios and showing how changes to tunables affect gameplay timing.

## Location

- **Route**: `/tuning` (only accessible in debug mode)
- **Access**: Gated behind `isDebugMode()` check from `src/lib/env.ts`

## Key Features

### 1. Simulation Engine (`src/lib/game/tuning-sim.ts`)

A standalone module that simulates game progression without modifying actual game state:

```typescript
interface SimulationState {
    resources: { money: number; loc: number; cred: number };
    upgrades: { vibeCode: Record<number, number>; delegation: Record<number, number> };
    projects: { standard: Record<string, number>; saas: Record<string, number>; openSource: Record<string, number> };
    techDebt: number;
    projectsShipped: number;
    totalClicks: number;
    timeElapsed: number; // in seconds
}

interface SimulationConfig {
    clickRate: number; // clicks per second
    passiveLocRate: number; // LoC per second
    techDebtReductionRate: number; // % debt reduction per second
    autoUpgradeThreshold: number; // % of upgrade cost to auto-buy
}

interface SimulationResult {
    timeToFirstPrestige: number; // seconds
    timeToSecondPrestige: number; // seconds
    techDebtAt4Minutes: number;
    timeToNextUpgrade: number; // seconds
    upgradeProgressOverTime: Array<{ time: number; owned: number; percentage: number }>;
    resourceRateOverTime: Array<{ time: number; locRate: number; cashRate: number; credRate: number }>;
}
```

### 2. Tunable Parameters

All game constants should be adjustable:

**Tech Debt System:**
- `TECH_DEBT.BASE_ACCUMULATION` (0.00008) - Base debt per click
- `TECH_DEBT.PER_PROJECT` (0.00001) - Additional debt per project
- `TECH_DEBT.DELEGATION_DEBT_RATE` (0.1) - Delegation debt rate
- `TECH_DEBT.MAX_DEBT` (0.5) - Maximum debt cap

**Upgrade System:**
- Upgrade cost multiplier (currently 1.15)
- Click power scaling (level × count)
- Delegation rate scaling (level + 0.02 × clickPower)

**Prestige System:**
- `PRESTIGE.THRESHOLD_PERCENT` (0.7) - 70% upgrades owned
- `PRESTIGE.STARTING_CASH_PER_POINT` (5000) - Starting cash per point
- `PRESTIGE.CASH_MULTIPLIER_PER_POINT` (0.20) - Cash multiplier per point
- `PRESTIGE.LOC_MULTIPLIER_PER_POINT` (0.15) - LoC multiplier per point

**Project Balancing:**
- Individual project costs and rewards
- Project unlock thresholds (cred requirements)

### 3. Metrics Dashboard

Display calculated metrics in real-time:

#### Primary Metrics
| Metric | Description |
|--------|-------------|
| Time to First Prestige | Seconds until 70% upgrades owned |
| Time to Second Prestige | Seconds from first to second prestige |
| Tech Debt at 4 min | Expected debt after 4 minutes of play |
| Time to Next Upgrade | Seconds until cheapest upgrade affordable |

#### Secondary Metrics
| Metric | Description |
|--------|-------------|
| Current LoC/sec | Projected passive generation |
| Current Cash/sec | Projected passive income |
| Debt Penalty Factor | Current (1 - debt)² modifier |
| Upgrade Cost Progression | Cost curve for next 5 upgrades |

### 4. Visualizations

Mermaid diagrams showing:
- Upgrade progression over time
- Resource accumulation curves
- Tech debt growth scenarios

### Step 4: Create Main Tuning Page

```svelte
<script>
    import { isDebugMode } from '$lib/env';
    import TuningControls from '$lib/components/TuningControls.svelte';
    import MetricsDisplay from '$lib/components/MetricsDisplay.svelte';
    import { simulateGameplay } from '$lib/game/tuning-sim';

    let config = $state(defaultConfig);
    let results = $derived(simulateGameplay(config));
</script>

{#if isDebugMode()}
    <h1>Game Balance Tuning</h1>
    <div class="tuning-layout">
        <TuningControls bind:config />
        <MetricsDisplay results={results} />
    </div>
{:else}
    <p>Debug mode required to access tuning page.</p>
{/if}
```

## Example Scenarios to Model

1. **Time to First Prestige**
   - With defaults: ~15-20 minutes?
   - With adjusted click power: ~10-12 minutes?
   - Impact of tech debt penalty: -20% at 30% debt

2. **Tech Debt at 4 Minutes**
   - Current: ~12% debt
   - With faster accumulation: ~25% debt
   - Impact of delegation: +0.1% debt/sec passive

3. **Time to Next Cheapest Upgrade**
   - Early game: ~30 seconds with active clicking
   - Mid game: ~2 minutes with passive generation
   - Late game: ~5 minutes with all upgrades

4. **Second Prestige Viability**
   - With prestige bonuses: 30% faster
   - Learning path debt relief: 50% less penalty

## Testing Scenarios

1. **Baseline**: Default constants - verify reasonable playtime
2. **Buffed**: Click power ×2, upgrade costs ×0.8 - verify faster progression
3. **Nerfed**: Tech debt accumulation ×2 - verify challenge increase
4. **Extreme**: Max debt 30%, no debt clearing - verify game still playable

## Notes

- Simulation assumes optimal play (always buying upgrades when affordable)
- Click rate is user-adjustable to simulate different play styles
- All metrics are projections based on mathematical models
- Actual gameplay may vary based on player behavior
